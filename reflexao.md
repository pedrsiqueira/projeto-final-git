## O que aprendi no minicurso

Antes do minicurso, meu uso de Git se resumia basicamente aos comandos básicos para subir arquivos no GitHub (`add`, `commit`, `push`). Ao longo das aulas e dos exercícios práticos, consegui entender como o versionamento funciona de verdade quando o projeto cresce ou envolve mais gente: trabalhar com *branches* separadas para não mexer direto na `main`, abrir *Issues* para planejar cada etapa, integrar alterações via *Pull Request* e publicar páginas direto pelo *GitHub Pages*.

## O que mais gostei na prática

A parte mais interessante foi sair da teoria e montar um fluxo completo nesse projeto final. Ver a divisão das tarefas funcionando na prática dá uma visão mais clara de como os repositórios reais são organizados. 

## Dificuldades durante o projeto

Acredito que a maior dificuldade foi pegar o ritmo de organização antes de sair codando: lembrar de trocar para a branch certa antes de alterar qualquer arquivo, quebrar o trabalho em commits menores, lembrar do padrão Conventional Commits e revisar os detalhes da documentação (como os links internos e a formatação em Markdown do README) para não deixar nada quebrado no repositório. Apesar de dar mais trabalho no início do que simplesmente subir tudo de uma vez, o resultado final fica muito mais limpo e fácil de acompanhar.
